# CTRGCN 与 SkeletonX 双人交互实验设计

日期：2026-09-07。状态：供小组讨论的实验方案，尚未执行训练；文中数量预算和验收阈值为建议值，不是实测结果。

本方案依据组员的 `Experiments.docx`、项目 `docs/Schedule.md`、数据划分指南及下列官方来源，覆盖实验方法、样本和评价标准。建议采用 CTR-GCN backbone + SkeletonX 策略作为主基线，同时保留纯 CTR-GCN。主要问题是：在相同训练条件下，保留人物配对特征并引入相对几何，是否改善双人交互识别，尤其是角色不对称类别？

## 1 基线与研究问题

SkeletonX 是跨样本特征聚合的训练框架，论文关注 one-shot 和 limited-scale 场景，可搭配 CTR-GCN；不应把它与 backbone 混为同一层级。复现时应冻结代码 commit、配对规则、聚合模块、损失及权重、特征接入位置和推理路径。全量交互子集训练属于本项目采用的新实验条件，不能直接拿论文 few-shot 数字比较。[1][2]

CTR-GCN 官方实现将人物维度并入 batch，经过共享骨干后，平均池化时空和人物维度；输入 BatchNorm 则具有与人物槽位相关的通道。因此它已有逐人编码，且不能仅凭最后平均池化就断言整个流程严格满足交换不变性。[3]

据此修订三个假设：

- H1：在相同 CTR-GCN 下，SkeletonX 是否提供训练收益？
- H2：相对于人物平均池化，保留双人配对信息、增加显式相对几何是否提供额外收益？
- H3：收益是否超过相似参数量控制，并且在预先定义的角色不对称类别上更明显？

这里的身份指一条序列内人物轨迹的连续对应，不是识别现实人物身份，也不把 performer ID 作为分类输入。动作分类标签通常没有给出哪个人物槽位是施动者；类别准确率提高只能支持交互分类改善，不能直接证明模型识别了施动者。[4]

## 2 实验样本与划分

### 2.1 主样本

使用 NTU RGB+D 120 官方 mutual actions 的全部 26 类：A050–A060 和 A106–A120。同时使用原始 NTU60 数据包与 NTU120 扩展包。标签映射为连续的 0–25，同时保存原始 action ID。一个样本是一条完整双人动作序列；训练裁剪片段不能被当作独立测试样本。[4]

按官方类名预先定义以下分析分组，属于本项目的语义分组，不是官方额外标签：

| 分组 | 类别 | 用途 |
| --- | --- | --- |
| 角色不对称候选 16 类 | A050–A054、A056–A057、A106–A111、A115–A116、A119 | 重点分析打、踢、推、递物、跟随、扶助等角色不同的动作 |
| 对称或相互动作候选 9 类 | A055、A058–A060、A112–A114、A118、A120 | 作为对照组 |
| 角色可能随片段变化 1 类 | A117 whisper | 单独报告，先检查训练样本再冻结归组 |

两位组员在查看测试结果前，根据类别定义和训练片段确认分组。A056 giving object 与 A118 exchange things 等容易混淆的类别应保留；不要只挑模型有明显提升的类。

### 2.2 数据协议

- 主协议：NTU120 XSub，使用官方 53 个训练主体名单；其余为测试主体。[5]
- 外部条件验证：NTU120 XSet，偶数 setup 训练，奇数 setup 测试。[5]
- 内部验证只从各协议的 official train 产生：XSub 暂取约 10% 的训练主体，XSet 暂取 2 个训练 setup；实际列表按类覆盖情况确定后固定。必须覆盖全部 26 类。
- 同一次表演的多个相机视角不得跨内部训练和验证集合；保存 `(S,P,R,A)` capture group。保持官方协议不变，不声称两位参与者的真实身份都能从文件名 P 完整审计。
- 使用内部验证选择超参数及训练轮数。冻结后在完整 official train 重训，以预先确定的轮数评测 official test。测试结果不得用于挑选消融结构。

### 2.3 数量与质控

主实验使用所有符合统一预处理规则的交互序列，不人为按类削减测试量。当前仓库未提供可统计的原始骨架和最终清单，因此不能预先声称准确的 train/test 数量，也不能按 26/120 比例推算。运行前导出每类原始数、缺失数、保留数、训练数、验证数、测试数。

统一排除官方缺失骨架列表及不可解析序列。对第二人缺失、轨迹短、追踪异常等情况采用预先冻结的规则；保留可处理的缺失帧并提供有效性 mask，禁止把补零关节当作真实坐标。报告异常及排除率，不得只为 proposed model 过滤困难样本。

建议先人工检查每类 10 条训练序列，共 260 条，关注人物追踪、中心化和骨架质量。这是开发质检规模，不是统计功效计算或测试样本量要求。可另建质量良好的成对子集用于诊断，所有模型必须使用完全相同的子集。

### 2.4 少样本补充

为检验 SkeletonX 的适用场景，可在 XSub 内设置每类 K=10、30 条训练序列，对应 260、780 条，使用嵌套抽样和固定清单，测试集保持不变。尽可能增加主体及 capture group 多样性，同时保证配对规则可执行；不得从验证或测试集补配对样本。

这应命名为“本项目自定义 K-shot 训练子集”，不是自动等同 SkeletonX 论文的 limited-scale 或 NTU one-shot 协议。报告额外使用的验证标签预算，以及每个 K 的实际人数、setup 数与独立 capture group 数。

## 3 实验方法

### 3.1 统一训练条件

主实验先使用 joint-only，输入 3D 坐标、25 关节、最多两人，暂定统一采样长度 T=64；该长度先通过开发集试跑确认。固定样本清单、骨架清洗、增强、初始化来源、优化器和学习率方案、训练步数规则、checkpoint 规则以及调参次数预算。

所有方法使用相同空间坐标系。相对位置必须在两人共享的平移、旋转和尺度变换后计算；若单人分支独立中心化，则另保留原始两人共同坐标用于关系分支。几何增强应对两人同步应用。记录时序采样间隔；速度在原时间轴估计再采样，或用实际采样时间差计算，不能把不等间隔差分当等间隔速度。

SkeletonX 配对仅从当前训练池取样；验证和测试按不依赖测试标签的推理流程运行。由于配对训练可能增加编码量，同时记录每轮骨干前向数量、总更新步数和 GPU 时长；不要仅凭 epoch 数相同宣称算力相同。

### 3.2 模型矩阵

| 编号 | 设置 | 主要比较 |
| --- | --- | --- |
| B0 | 原始 CTR-GCN | 基础参照 |
| B1 | CTR-GCN + 完整 SkeletonX 策略 | B1−B0：策略收益；项目主基线 |
| M1 | B1 + 保留人物配对特征的融合 | M1−B1：融合方式收益 |
| M2 | M1 + 相对位移、距离、速度 | M2−M1：显式几何收益 |
| C1 | B1 + 不访问逐人配对信息的容量匹配 head | 排查增加参数的解释 |
| C2 | M2 关闭 SkeletonX | 与 B0/B1/M2 构成策略与表示的 2×2 对照 |
| P0 | 标准 PoseC3D 融合热图 | 跨表示参考，不能单独用于因果归因 |

M1 的最小研究定义是：提取人物池化前的共享骨干特征 hA、hB，将原来的简单人物平均替换为保留配对关系的轻量融合，例如使用 `hA+hB` 与 `abs(hA-hB)`。空间与时间池化位置应明确。该设计对最终 pair head 的输入交换对称，但整个模型还需审计预处理和 BatchNorm。不要将“新增两套不共享 backbone”作为默认方案，也不要把已有逐人编码包装为新增贡献。

M2 的候选关系输入为同名关节相对位移 r_j(t)=x_Bj(t)−x_Aj(t)、距离 d_j(t)=||r_j(t)||、相对速度 v_j(t)=Δr_j(t)/Δt。使用共同尺度和有效帧 mask。双向有序关系分别编码后对称汇聚，保留关系方向的编码能力，同时使最终动作分类不依赖 A/B 槽位名称。

距离是位移的确定性函数，所以距离分支的作用只能解释为更易学习的几何归纳偏置，不能声称增加了新的独立信息。M1 接入 SkeletonX 的具体张量位置需在实现前核对官方特征输出；所有 proposed 变体保持同一接入位置。

容量控制 C1 分别接近 M1、M2 的参数量，目标误差 ≤5%；输入只能是基线已融合的特征。同时报告计算量差异，参数接近不等于计算等价。

### 3.3 对组员四项实验的细化

**实验一 基线与融合诊断。** 比较 B0、B1、P0，建立性能和错误分布。它们使用不同 backbone 或输入维度时，只能说明整体方法差异。如果要进一步论证热图融合的信息影响，应在同一 PoseC3D 框架中增加共享权重逐人热图编码与晚融合对照，统一骨架来源、投影、热图分辨率、训练预算，并报告计算开销。没有这项对照时，把“融合造成身份损失”写为待验证机制。

**实验二 组件分析。** 先比较 B1→M1→M2，再运行 M1+位移、M1+位移+距离，以及 M2 去掉位移、去掉距离、去掉速度。逐项累加反映条件下的增益，不能单独识别所有独立作用；删除式消融用于确认完整模型是否实际依赖该分量。配合 C1 和 C2 排查容量与 SkeletonX 策略解释。

**实验三 人物交换。** 将两种测试分开：

1. 整段槽位交换：在全部帧交换 A/B，并同步交换 mask、置信度和人物特征；关系量同步重算。对当前 26 类序列级动作标签，预期类别不变，包括 pushing、giving object 等角色不对称类别。交换索引没有改变真实动作。分别在预处理前和最终模型输入处交换，可定位排序、中心化或网络本身的敏感性。
2. 时序身份打断：在序列 25%、50%、75% 位置分别把后续 A/B 互换，另可增加短片段交换。所有方法使用相同扰动版本，先在质量良好的双人轨迹上诊断。该操作保留逐帧无序骨架集合，却打断逐人轨迹；报告相对干净输入的退化。它同时引入轨迹跳变，不能视为完全排除运动不连续因素的纯身份因果实验，也不能认为退化越大模型越好。

对无身份区分的逐帧融合热图，上述交换原则上不改变热图，可作为诊断管线的 sanity check；若输出明显变化，应先检查生成和评测流程是否引入随机性。

**实验四 不对称交互。** 在完整 26 类模型的同一组测试预测上分别统计两个预先定义分组及每类 recall；不重新训练一个只识别挑选类别的模型，也不屏蔽分组外的预测后重新归一化。报告 `不对称组提升−对称组提升` 及不确定性。案例应覆盖改善、仍错误、回退三类，按冻结的抽样规则挑选。

如要直接主张“识别谁是施动者”，需另加角色标注和人物级评测：两位组员独立标注可判定片段的 actor track，分歧复核，保留不明确标签；在训练侧拟合角色 probe，测试侧只评测，报告 actor identification accuracy 和可判定覆盖率。没有这些标注时，结论限定为动作分类与轨迹连续性分析。

## 4 评价标准

### 4.1 指标定义

| 维度 | 指标 | 使用方式 |
| --- | --- | --- |
| 主要终点 | 26 类 Macro-F1 | 主比较 M2−B1；每类先算 F1 再平均 |
| 整体识别 | Top-1 accuracy | 完整序列预测正确比例 |
| 类别公平性 | 每类 recall、macro recall、类支持数 | 重点检查不对称类，公开全部 26 类 |
| 顺序一致性 | 整段交换预测翻转率 | mean(argmax p(x) ≠ argmax p(swap(x))) |
| 概率一致性 | 平均 total variation | mean(0.5 × sum_c abs(p_c(x)−p_c(swap(x)))) |
| 扰动退化 | ΔAccuracy、ΔMacro-F1 | clean 分数减去各扰动强度分数；注明百分点 |
| 效率 | 参数、计算量、吞吐、延迟、峰值显存 | 分开记录训练与部署推理成本 |

整体交换准确率差接近零仍可能出现大量相互抵消的预测翻转，因此不能只记录一个 accuracy drop 作为 identity-swap sensitivity。仓库现有同名指标在落地时必须明确映射到哪一定义，并保留其余指标。

吞吐采用同一 GPU、batch、T、精度、预热和同步方式，明确是否包含预处理及数据传输；另报告 batch=1 的中位延迟和 P95。记录设备型号、软件版本及测量重复次数。SkeletonX 训练辅助模块与实际推理保留模块分别计数。

### 4.2 重复与统计

核心 B0、B1、M1、M2 使用相同的 3 个预先固定 seed，报告均值与标准差，不只报告最好 seed。少样本实验固定配对抽样清单，并区分样本选择随机性和训练初始化随机性；预算允许时对多个子集重复。

保存每个样本的标签、预测类别和概率，在同一测试样本上作配对比较。95% bootstrap 区间按 subject 或 capture group 成组重采样，避免把同一表演的多个视角当独立证据；明确分组定义，并单独报告 seed 波动。样本 bootstrap 不能代替训练重复，也不把三个 seed 的同一样本当三份独立测试样本。

预先指定主要比较 M2 vs B1 和主要终点 Macro-F1；大量逐类和消融比较属于探索性分析。若正式逐类检验显著性，采用 Holm 等多重比较校正。小类别的区间可能很宽，应同时给出支持数，不以少数案例推断总体。

### 4.3 建议的结论判定

以下为项目内部目标，需在最终测试前冻结，不是文献规定：

- 实用收益目标：XSub 的 M2−B1 Macro-F1 平均提升至少 1.0 个百分点，且配对 95% 区间下界大于 0；同时完整公开 Top-1 和 seed 波动。
- 泛化证据：XSet 同方向改善；若不成立，结论限定于 XSub，不宣称普遍改善。
- 机制证据：M2 对比容量控制仍有优势，关键删除式消融下降，不对称组有可解释且带区间的结果。证据不足时不作强因果表述。
- 部署目标：推理参数增量 ≤10%，吞吐下降 ≤15%；若超过，报告性能与开销权衡，不据此隐藏结果。
- 对明确设计为严格交换不变的整条确定性流程，输出误差应处于预先通过数值测试确定的浮点容差内。仅经验性采用交换增强的模型，应报告实际翻转率，不能声称数学不变性。

未达到提升阈值仍是有效研究结果：可能说明原始逐人编码已足够、显式几何冗余，或收益只出现在少样本条件。工程验收与研究假设成立必须分开。

## 5 执行顺序与交付

1. 冻结 26 类清单、官方划分、内部验证和质量规则，生成数量表；核对基线特征池化位置和 SkeletonX 配对可用性。
2. 用 B0、B1 各一次试跑测量收敛、显存及 GPU 时长；仅据开发验证决定训练预算。
3. 在 XSub 完成 B0/B1/M1/M2 开发比较及融合和几何消融，冻结最终设计。
4. 完成核心正式重复：4 模型 × 2 协议 × 3 seeds = 24 次训练。C1/C2、PoseC3D 和更细消融另计，不能把它们隐含在 24 次内。
5. 对已有 checkpoint 做整段交换、身份打断和分组评测，无需为每种扰动重新训练。少样本补充可先限于 B0/B1/M2、K=10/30、XSub。
6. 预算估算使用试跑实测每次时长求和，再加预处理、评测和失败重跑余量。项目原先 20–60 GPU-hours 只是目标，当前无法保证容纳全部矩阵。预算不足时先完成 XSub 核心三 seed 与容量控制，再安排 XSet；未完成的泛化验证须披露。

建议小组分工：数据负责人维护清单与追踪质检；基线负责人维护 B0/B1 与训练公平性；表示负责人维护 M1/M2 与消融；评价负责人维护交换测试、统计及盲选案例。人员不足可兼任，但评价规则先共同冻结。

最终交付包括：样本数量与排除表、模型主结果表、组件消融表、交换与身份打断表、26 类混淆矩阵和逐类 recall、改善及失败案例，以及每次运行的 config/commit/seed/数据指纹/checkpoint/逐样本预测/环境/GPU 时长。所有结果必须能追溯到运行记录。

现有 harness 尚无实际训练入口，M1/M2 配置名称仍为 DGCN/POM，与本方案不完全一致。本次只形成设计文档；正式实施时应单独同步实验定义、调度依赖、指标语义和相关说明，不将当前占位配置当成模型已经实现。
